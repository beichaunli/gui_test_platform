# GUI TestLab：Windows 软件自动遍历测试平台

本项目用于在 Windows 上自动操作图形界面软件、观察执行情况并保存完整测试过程。只接入 GUI EXE，采用一种测试方法：**基于界面状态的广度优先遍历（BFS）**。

平台展示真实窗口截图，记录正常、失败、跳过、恢复与停止事件，提供功能范围、状态图、问题证据及离线报告。它不修改被测软件、不生成修复补丁，也不要求每次测试都发现缺陷。

## 二、环境配置

1. Windows x64，并保持当前登录桌面解锁。
2. 安装 Python 3.11 或以上，建议 Python 3.13 / 3.14 x64。
3. GitHub 源码版不包含本机 GUI 依赖，首次使用须运行下方的 setup_gui.py。若使用另行提供、附带匹配版本依赖的离线交付 ZIP，则可跳过安装。
4. 不需要 Android、ADB、Node、前端编译或云账号。

先在**项目根目录**打开普通终端，检查环境和随附文件：

```powershell
python source_code/check_project.py
```

如果显示 `Matching GUI dependencies: False`，或使用其他 Python 版本，请执行：

```powershell
python source_code/setup_gui.py
```

首次补装需要联网，依赖安装在本项目内，不写入全局 Python 包目录。安装依赖与启动服务必须使用同一个 Python；例如使用 `py -3.13`，则上述所有 `python` 命令都相应替换为 `py -3.13`。

## 三、启动平台

方式一：双击 **`source_code/start.bat`**。启动器会打开浏览器；已经运行时直接连接已有平台，不重复启动。8877 被其他程序占用时会尝试后续可用端口，以终端显示的访问地址为准。

方式二：在项目根目录执行：

```powershell
python source_code/server.py
```

浏览器访问：**http://127.0.0.1:8877**。

端口被占用时可以改为：

```powershell
python source_code/server.py --port 8878
```

然后访问对应端口。直接运行 server.py 是严格端口模式；已经存在服务时会提示端口占用，这是防止新旧服务混用。日常使用建议双击 start.bat。结束服务应在最初启动服务的终端中按 Ctrl+C，更新文件后重启服务，再在浏览器按 Ctrl+F5 刷新。

## 四、第一次测试

1. 点击“使用随附 Notepad++ 示例”。软件路径显示为：

   ```text
   source_code/tested_software/notepad++/notepad++.exe
   ```

2. 点击“检查接入”，平台实际启动软件并检查窗口和控件，检查结束关闭本任务创建的实例。
3. 建议设置 1 轮、30～35 次操作预算；范围设置中深度可设为 4。
4. 点击“开始测试”。默认后台控件模式不会主动移动鼠标；可以操作平台或其他窗口，但不要手动修改被测软件的状态。
5. 查看窗口截图、全部事件、功能范围与状态图；点击事件查看前后画面、控件、输入和判断依据。
6. 可以中途停止，已执行记录保留，并生成部分测试报告。
7. 结束后查看或导出 HTML、JSON 和证据 ZIP。新记录生成在 `source_code/data/`，首次启动会自动创建该目录。

界面为周期截图预览，不是视频流。路径恢复默认折叠，但每一步仍保存，可展开查看或选择“恢复操作”筛选。

### 鼠标、焦点与停止

范围设置新增两种交互方式，测试算法仍然只有 BFS：

- **后台控件操作（默认）**：使用窗口消息、菜单命令和控件接口，不主动移动系统鼠标、不发送全局键盘输入。不支持后台操作的步骤明确跳过，绝不悄悄切换到真实鼠标。
- **前台真实输入**：用于兼容依赖真实输入的软件，会移动鼠标并切换焦点，运行时不适合同时进行其他桌面操作。

后台模式已对随附 Notepad++ 的 15 类功能完成实际验证，但它不等于验证鼠标命中区域，也不保证任意软件支持后台操作。软件自身创建弹窗时仍可能激活窗口；如需与日常工作完全隔离，建议在虚拟机中运行整个平台。

服务启动时注册 **Ctrl+Alt+F12**，可以在其他窗口获得焦点时请求停止当前任务。页面会显示快捷键是否注册成功；被其他程序占用时仍可使用网页停止按钮。停止后保存全部已有记录及部分报告。同一时间建议只启动一个平台服务。

## 五、测试方法和范围

平台读取控件树，识别状态并生成动作队列。按 BFS 优先探索浅层分支，必要时重启本任务实例并重放路径。到达目标状态后才执行新动作，避免在错误界面继续操作。

Notepad++ 档案包含 15 类功能：新建、普通文本追加、多行与 Unicode 输入、全文选择、撤销、重做、普通文本打开、UTF-8 文件打开、另存为、查找、替换、指定行跳转、自动换行、缩放和行尾转换。

检查包括实际查找选区、替换后的完整内容、光标行、输出文件内容等。同一轮按功能与场景去重，避免反复新建和编辑。预算是上限，场景队列提前完成后不会为了凑次数重复操作。

“已执行操作”和“功能检查通过”分别标注。输入被正常拒绝、环境错误和疑似软件问题分别记录；错误提示不自动认定为漏洞。没有源码堆栈时定位到事件、窗口、控件和输入，不伪造源码行号。

## 六、相对路径与换目录运行

内置目标、项目内 EXE 和文件参数以项目根目录为基准，使用相对路径存储和显示；不依赖终端当前工作目录，不写死开发者机器目录。

例如 `source_code/tested_software/notepad++/notepad++.exe` 始终指向**本项目中的文件**。把整个文件夹改名、移动、复制到其他磁盘后，程序会根据当前代码位置重新定位。

Windows 启动进程时，平台会临时计算当前机器的完整路径，这是实际执行所需，并不表示配置绑定原电脑。运行截图、窗口标题或诊断中可能出现当次机器的真实路径，属于实际证据。

“选择 EXE”仍允许测试本机外部软件。项目内的选择会转换为相对路径；项目之外的 EXE 是本机外部依赖，不能保证老师电脑也存在。课程验收建议使用随附软件，或将允许分发的软件及必要组件放入 `source_code/tested_software/` 后再选择。

启动参数每行一项，`{work}` 表示任务专用样本目录，`{sample}` 表示该目录中的样本。项目内现有的相对文件参数也会按项目根目录解析。

## 七、测试其他 EXE

选择软件主程序，先“检查接入”，首次用 1 轮、5～10 次小预算。Win32 后端适合传统控件，UIA 后端适合暴露可访问性控件的界面。

通用模式能探索按钮、菜单、文本框、标签页和下拉框，但不知道所有业务的正确结果。复杂流程需要软件档案；自绘界面、游戏、单实例转交或权限不匹配可能无法直接接入。

仅使用专用测试数据。平台不是安全沙箱，排除关键词不能代替对软件副作用的了解。不要用带有私人重要数据的窗口或目录进行探索。

## 八、常见问题

- **“GUI 依赖未就绪”**：用启动服务的同一个 Python 运行 `source_code/setup_gui.py`，完成后重启。
- **“没有活动桌面 / There is no active desktop”**：保持桌面解锁、远程会话连接，从当前登录用户的普通终端启动。不要在 Windows 服务、非交互会话或受限沙箱中执行 GUI 输入。截图可见不代表鼠标键盘操作权限可用。
- **只能看到初始界面**：查看接入检查和事件原因，检查权限、控件后端以及是否需要独立实例参数。
- **任务完成但预算百分比不足 100%**：预算是上限；可执行场景已完成时会提前结束，实际范围以功能清单和记录为准。
- **没有发现问题**：这是允许的结果，报告会列出已执行、未执行和无法检查的范围，不代表软件完全没有缺陷。
