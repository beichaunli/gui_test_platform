# GUI 软件测试平台：项目需求提示词与对话记录

整理日期：2026-11-05。

本文件先给出项目总体需求与实现提示词，再按顺序整理本次 GUI 平台的讨论过程，便于阅读者先了解要做什么，再了解需求如何完善。第一部分由用户已确认的要求整合而成，不冒充最初一次消息的逐字原文；第二部分中的助手回应均为摘要，不是产品原生聊天导出。IDE 路径、内部工具输出、会话令牌和原始截图附件不纳入。

## 一、项目总体需求与实现提示词（整合版）

### 1. 项目背景与目标

请实现一个用于软件安全课程实验和答辩演示的软件自动化测试平台。可以借鉴老师示例的需求组织方式和项目完成度，重点参考自动执行、真实测试画面、逐步记录、停止控制和结果报告，结合以下实际需求独立实现。

平台只负责执行测试、观察问题和提供定位依据，不修改被测软件、不生成补丁，也不提供自动修复。测试不一定要发现软件缺陷；即使没有异常，也应清楚说明测试了什么、执行了哪些步骤、哪些结果得到验证、哪些范围尚未覆盖。

建议项目名称：**基于界面状态遍历的 Windows 软件自动化测试平台**。

### 2. 运行环境和接入对象

- 在 Windows 本地运行，使用中文浏览器界面，不需要云账号、手机、Android 模拟器或云端服务。
- 只接入 Windows 图形界面 EXE 软件，提供文件选择按钮，也允许输入软件路径。
- 不能把平台限制为压缩软件，也不能只能执行某一个软件的固定按钮流程。
- 对能暴露标准 Windows 控件或 UI Automation 控件的软件提供通用探索；启动器、单实例、自绘界面和权限限制应明确说明，不承诺任意 EXE 无配置全面兼容。
- 提供“检查接入”：实际启动被测软件，显示窗口及控件识别情况。不能启动、找不到窗口或无法识别控件时，给出具体原因。

### 3. 唯一测试方法及测试范围

采用**基于界面状态的广度优先自动遍历测试（BFS）**，不设置多种测试算法选择。

平台应读取窗口与控件树，识别当前状态，生成可执行的点击、菜单、输入、选择及窗口操作，维护状态和分支队列。优先探索较浅分支，必要时重启本任务的软件实例并重放已有路径，确认到达目标状态后再执行新动作。

测试应尽可能覆盖约定的主要功能，而不是只重复点击少量按钮。需要状态去重和场景去重，避免文档标题变化就重新测试同样的功能。已具备当前状态时应尽量复用；必要的恢复操作可以重复，但必须与正式测试动作分开记录。

“较全面”以明确的功能清单、可操作界面和实际执行证据说明，不将点击次数或预算百分比当作全软件覆盖率。未知软件没有业务清单时，只报告观察到的状态和操作范围。

### 4. 被测软件与功能检查

选择适合 GUI 自动化的真实开源桌面软件作为演示对象，随项目提供可运行程序、必要组件、许可证、来源及版本信息，避免老师下载后找不到目标。

初始演示至少覆盖五类主要功能，后续将 Notepad++ 档案完善为 15 类：新建、普通追加、多行与 Unicode 输入、全文选择、撤销、重做、普通文本打开、UTF-8 打开、另存为、查找、替换、行跳转、自动换行、缩放和行尾转换。

检查应尽量深入实际结果，例如查找后核对选区、替换后核对内容、跳转后核对光标行、保存后核对输出文件。没有明确检查点时只能标注“操作已执行，未验证功能正确性”，不能把打开对话框直接认定为业务完全正确。

### 5. 测试画面与界面布局

顶部集中放置软件选择、主要预算、开始、停止及醒目进度。主体突出真实软件画面和测试过程记录，字体清晰，长内容在板块内滚动，复杂参数折叠显示。

软件真实打开后，持续更新目标窗口截图；操作事件保存前后画面，并能高亮目标控件。支持实时跟随、点击历史事件回看截图及返回实时，不能用模拟图片代替真实测试现场。

提供全部记录、功能范围、状态图、待复核问题和任务历史。异常不是唯一可见内容，正常操作也应直观展示。

### 6. 全量记录、任务控制与鼠标使用

支持设置测试轮数、每轮操作预算、总时长、单步超时、动作间隔和探索深度，并提供合理默认值。预算是上限，场景提前遍历完成后不应为了凑次数重复执行。

每一步都保存任务、轮次、事件编号、时间、动作、输入、窗口、控件、状态、截图、耗时、结果及原因。正常、失败、跳过、恢复、启动和停止全部记录，不能只保存异常。必要的路径恢复可以在页面折叠，但记录不能删除。

测试中途可停止；收到停止请求后不再安排新动作，保存已有证据并生成部分完成报告。仅结束本任务创建的进程，不影响用户事先打开的无关软件。

默认提供不主动移动系统鼠标或发送全局按键的后台控件操作，保留前台真实输入作为兼容选项。后台不支持的操作应明确跳过，不暗中切换到真实鼠标。提供 Ctrl+Alt+F12 停止快捷键并显示注册状态。软件自身弹窗仍可能激活窗口，完全隔离可使用虚拟机。

### 7. 问题观察、定位与报告

记录意外退出、无响应、超时、错误提示和检查失败，并区分软件问题、配置错误与运行环境问题。损坏输入被正常拒绝或控件工具调用失败，不能直接认定为漏洞；没有活动桌面等环境错误应及时中断并说明原因。

问题定位至少包括具体事件、前后操作、窗口、控件、输入与截图。有可靠堆栈时再展示源码位置，不伪造错误行号，也不把鼠标点击位置当作软件内部根因。

任务完成或主动停止后都生成报告，说明目标版本、环境、方法、预算、实际范围、全部事件、问题证据和限制。支持 HTML、JSON 和证据 ZIP，服务关闭后仍可查看导出的材料。允许结论为“在本次范围和预算内未观察到问题”。

### 8. 项目交付与验收

交付根目录仅保留以下内容：

```text
prompt/       只有一个文件，包含本节项目需求和后续 GUI 对话
source_code/  源代码、依赖配置、测试以及随附被测软件
video/        演示视频目录，初始预留为空，后续可加入真实录屏
README.md     项目介绍、环境配置、启动与使用说明
```

项目内软件、样本和配置使用以项目根目录为基准的相对路径，运行时依据当前代码位置解析；老师下载到其他目录、改名或从其他工作目录启动时，随附目标仍应可用。外部自选 EXE 的本机依赖应单独说明。

验收重点为：真实软件能启动和自动操作，BFS 能探索多个分支，主要功能有执行与检查依据，每个过程均有记录，画面可回看，停止可靠，报告可导出，以及换目录可复现。自编测试夹具必须标注，不能冒充真实软件验收。无需强制发现漏洞，也不以异常数量评判平台完成度。

## 二、GUI 平台需求讨论与实现记录

以下保留需求提出、澄清及迭代顺序。早期阶段的具体功能数量和实现结论反映当时版本，当前整合要求见第一部分。

### 1. 收敛为一种对象和一种测试方法

用户：这个软件测试平台只用于测试，发现问题所在，不用于修复。并且你说的三类对象接入太过于复杂，我需要的只是一种接入对象即可，最好能够显示软件测试的画面，另外测试方法不需要太多，选择一种较为常用的测试方法即可。老师的测试过程是对软件进行全面的测试，中途可以停止，每个测试过程都具有记录，不是只记录异常问题。本测试软件不一定需要测试出被测软件的问题，但是需要实现对于被测软件的较为全面的测试，结合这个修改我的需求。

附件说明：用户展示老师平台的测试参数、真实应用画面和逐事件截图记录。

助手摘要：确定只接入 Windows 图形界面 EXE；采用基于状态的广度优先遍历，展示真实窗口、全量事件和可停止任务。取消多对象、多方法、自动修复及必须发现漏洞要求。较全面测试以约定功能清单和实际证据说明，不宣称覆盖任意 EXE 的全部业务。

### 2. 确认 V3 并请求新平台

用户提供完整 V3 需求，要求：基于一种测试方法以及 UI 图形界面可展示性、被测 EXE 可选择性，以及测试的通用性，设计一个全新的软件测试平台。

确认的关键要求：

- Windows 本地中文网页，仅 GUI EXE 接入。
- BFS 维护界面状态、分支队列及到达路径，必要时恢复并探索其他分支。
- 保存正常、失败、跳过、恢复、停止等全部操作及前后截图。
- 实时跟随、历史回看、功能范围、可中途停止和离线报告。
- 接入限制、预算进度和检查结论明确，不伪造源码位置或业务覆盖率。
- 选择一个适合自动化的开源软件，随附程序、样本、许可和复现说明。

助手摘要：独立实现 GUI TestLab；保留原项目。使用 Notepad++ 原版便携软件验证多功能，另用其他 EXE 检查通用控件探索。运行配置、任务、事件、截图、状态图和报告统一管理。

### 3. 桌面环境错误

用户：这是为何？

附件说明：六项操作出现 `There is no active desktop required for moving mouse cursor!`，只观察到一个界面状态，列表显示多条操作失败。

助手摘要：确认是运行进程无法操作交互桌面，不是被测软件缺陷。服务改在可操作桌面的环境启动。程序遇到该错误时立即中断，记录中文环境原因，不继续制造多条软件问题；依赖就绪与桌面操作权限分别说明。

### 4. 解释测试方法

用户：当前的软件测试方法是什么？

助手摘要：采用基于界面状态的广度优先自动遍历测试。读取控件、生成动作、探索浅层分支，再恢复到指定状态继续探索；保存每一步证据。有业务检查点时核对结果，否则只说明操作执行情况。

### 5. 接入其他 EXE

用户：如果我导入其他的 exe 文件能否进行测试？

助手摘要：可以选择其他 EXE 并先检查接入。通用模式探索可识别控件，但不会套用 Notepad++ 的功能清单，也不能自动判断所有业务正确性。自绘控件、权限、启动器和单实例机制可能需要配置或适配。

### 6. 丰富功能并减少重复

用户：我觉得当前的对于 notepad++ 的测试可以丰富一些、复杂一些。当然还是基于当前的测试方法。毕竟我通过页面观察到有很多很多的重复的测试。

助手摘要：排查出相同六项操作在每个新状态被重新排队的问题。扩展到 15 类功能：新建、普通追加、多行与 Unicode、全文选择、撤销、重做、普通文本打开、UTF-8 打开、另存为、查找、替换、行跳转、自动换行、缩放及行尾转换。

同轮按功能与场景去重，撤销/重做有前置条件，空白文档不继续新建。查找检查实际选区、替换检查内容、行跳转检查光标，保存核对当前编辑内容。恢复记录保留并默认折叠，当前状态可复用时不无条件重启。

真实验收摘要：15 类配置检查通过，25 次测试动作、24 个状态、91 条事件，去重 98 个候选操作。该结论仅对应受控样本和检查点，不代表软件所有业务均正确。

### 7. 整理交付与相对路径

用户：我发现一个问题，这里使用的是绝对路径，这个绝对路径是不对的，由于这个项目需要老师下载并验证，如果绝对路径可能会出错，需要你调整到相对路径。另外我需要你将这个项目整理，就整理为这几个，题词里只包含一个文件，也就是本次 GUI 的对话，source 中包含源代码以及被测试软件，视频中空着先，然后就是一个本项目的说明文件，指出该项目是什么，怎么配置怎么运行。

助手摘要：交付根目录收敛为 prompt、source_code、空 video 和 README.md。prompt 仅保留本文件；被测软件、测试数据及设计说明放入 source_code。原始开发任务与报告另行备份，不混入首次运行历史。

项目内软件路径按项目根目录相对显示与存储，启动时依据当前代码位置解析，不依赖开发者目录或终端当前目录。根 README 提供环境、配置、启动、测试方法、路径规则及常见问题。外部自选 EXE 仍属于本机依赖，老师验收默认使用随附目标。

### 8. 自动测试期间自由操作鼠标

用户：现在没有问题，但是有一个小情况，就是在自动执行期间，鼠标是无法不动的，每次执行命令时鼠标会自动移动到某个位置，有无方法，在自动测试过程中能自由控制鼠标，不然点击停止都成问题。

助手摘要：新增默认后台控件模式，菜单、按钮及编辑输入改用窗口消息和控件接口，避免平台移动鼠标和发送全局按键；原前台输入作为兼容选项。不支持的后台步骤明确跳过，不隐式抢占鼠标。增加 Ctrl+Alt+F12 停止快捷键，并提示注册状态。修复 Windows 端口重复监听，防止新旧服务混用。

后台模式对随附 Notepad++ 的 15 类功能实际验证通过。软件自身弹窗仍可能激活窗口，后台测试不是完全桌面隔离；需要完全隔离时使用虚拟机。全过程和停止记录继续保存。

### 9. 重复启动与端口占用

用户提供终端截图，显示“端口 8877 已被占用或不可用”。

助手摘要：核对后确认平台服务已经运行，重复启动触发端口保护。日常启动入口改为 launcher：发现本平台已经运行时连接已有服务并打开页面；端口由其他程序占用时尝试后续可用端口。保留 server.py 的严格端口模式，避免新旧实例共享端口。启动方式及差异写入根 README。
